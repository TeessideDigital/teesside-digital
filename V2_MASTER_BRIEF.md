# 23. INTERACTIVE SHOWCASE / WEBSITE HEALTH CHECK

The current Website Health Check concept is useful:

Give visitors a technical experience while demonstrating capability.

However, the implementation must be reviewed critically.

Browser-side cross-origin fetching cannot reliably inspect arbitrary external websites.

It also cannot truthfully verify many server-level characteristics from HTML alone.

Do not preserve the current implementation simply because it exists.

Options:

A. Build a legitimate server-side diagnostic system with strict SSRF protections and well-defined checks.
B. Narrow its claims to match what it can actually analyse.
C. Replace it with a stronger interactive technical showcase.

If implementing server-side URL fetching, consider:

- SSRF
- private IP ranges
- loopback
- link-local addresses
- DNS rebinding
- redirects
- IPv6
- cloud metadata endpoints
- timeouts
- response size limits
- allowed protocols
- content type
- rate limiting
- abuse prevention

Never build a naive open proxy.
